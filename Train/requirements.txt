# Python dependencies for the ARO training pipeline.
#
# Installed into Train/.venv by `Train/training.sh`.
#
# ── Why the load-bearing packages are pinned ────────────────────────────────
# This file used to pin nothing at all, under a comment saying "pin only where
# load-bearing" — which in practice meant `pip install --upgrade` resolved a
# different stack on every run, and the model that shipped could not be rebuilt
# from the repository (GitLab #792). Worse, that upgrade silently replaced the
# mlx build the 30B MoE LoRA run depends on (GitLab #793).
#
# So: the training/inference stack is pinned. The notebook-execution and
# plotting stack is floored (`>=`) — those only have to be new enough, and a
# security fix there should not need a commit here.
#
# `requirements.lock.darwin-py312.txt` is the full transitive freeze of the
# environment that produced the last release; install that instead when you
# want byte-identical dependencies rather than merely compatible ones.
# Regenerate it with:
#     Train/.venv/bin/pip freeze > Train/requirements.lock.darwin-py312.txt

# ── Notebook execution ───────────────────────────────────────────────────
jupyter>=1.1

nbclient>=0.10

ipywidgets>=8.1

# ── Hugging Face stack ───────────────────────────────────────────────────
# Pinned: the chat template applied at training time must be the one applied

# ── MLX (Apple Silicon only — pip skips these on Linux/Windows) ──────────
# A floor rather than an exact pin, and the floor is 0.32.2: that is the first
# release whose shipped metallib carries the float32 `steel_gather_mm_rhs_nax`
# instantiation LoRA on a MoE teacher needs (see ISSUE-MLX.md). Below it,
# training crashed unless you had built mlx from source with a one-line patch.
# A floor lets bug fixes in while keeping the crash out — and
# `Train/script/mlx_preflight.py` verifies the kernel is actually present in
# the installed metallib rather than trusting the version string alone.
mlx>=0.32.2; sys_platform == "darwin"
mlx-metal>=0.32.2; sys_platform == "darwin"
mlx-lm>=0.31.3; sys_platform == "darwin"
