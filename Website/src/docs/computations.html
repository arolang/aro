Computations

Compute derives a new value from an existing one. The qualifier picks the operation; the result name is yours.

Compute belongs to the OWN semantic role: it transforms data inside a feature set without reaching outside it. Reach for Create when you are making a new literal, and Compute when you are deriving something from a value you already have. 

Compute the <total> from <price> * <quantity>.
Compute the <digest: sha256> from the <payload>.
Compute the <safe: html-escape> from the <comment>.

Qualifier-as-name

Write Compute the <length> from the <message>. and the result name is the operation. That is fine until you need two of them in one feature set — names are immutable, so the second would have nowhere to go. Split them with a qualifier: the base becomes the variable name, the qualifier selects the operation. 

(* Name and operation are the same word *)
Compute the <length> from the <message>.

(* Name and operation separated — now you can have both *)
Compute the <first-length: length> from the <first-message>.
Compute the <second-length: length> from the <second-message>.

The qualifier namespace is closed

A Compute qualifier must resolve to a built-in from the tables below, a plugin qualifier (handle.qualifier), a chain (a|b), or a date offset (-7d). Anything else is an error that names the closest match: 

error: Unknown Compute qualifier 'lenght'
  hint: Did you mean 'length'?
  hint: Run `aro actions --qualifiers` for the full set

aro check rejects unknown qualifiers too, so a green check means the qualifier exists. Namespaced names and chains are accepted at check time and resolved at run time, because aro check does not load plugins. Run aro actions --qualifiers for the live set, plugins included.

Escaping and templates

A template whose path ends .html or .htm escapes what it prints. .tpl, .txt and .md do not — so a .tpl emitting HTML still needs html-escape. Never hand-escape into an escaping template, or your reader sees &amp;lt;.

Arithmetic

Compute also takes an expression directly, with the usual + - * / % and the precedence you expect. 

Compute the <subtotal> from <price> * <quantity>.
Compute the <taxed> from <subtotal> * 1.19.
Compute the <total: fixed> from <taxed>.

fixed is the one to reach for with money: it rounds to two decimal places unless you say otherwise.

Chaining

Qualifiers chain with |, each stage resolving like a lone qualifier:

Compute the <slug: lowercase|trim> from the <title>.

Plugin qualifiers

Plugins contribute qualifiers under their own handle, so there is never a collision with a built-in: 

Compute the <pick: collections.pick-random> from the <items>.
Compute the <ranked: stats.sort> from the <numbers>.

See Writing Extensions for how a plugin declares them.

Two things that are not qualifiers

Both of these are common enough that the check-time diagnostic names them:

  • Sorting, reversing and element access are actions. Sort the <ranked> for the <users> by "score"., Reverse the <backwards> for the <items>., Extract the <first-item: first> from the <items>.
  • A result type uses as, because the qualifier slot is already spoken for by the operation: Compute the <n> as Float from <s>.

Specification
