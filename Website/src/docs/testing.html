Testing

Tests are feature sets that live in the same file as the code they exercise — Given, When, Then, and nothing else to set up.

Tests live beside the code they test

A test is a feature set whose business activity ends in Test (or Tests). There is no test directory, no test runner to configure, and no setup or teardown — everything inside the feature set is the test. The compiler strips them out of native binaries, so shipping them costs nothing. 

(* Production code — included in the binary *)
(get-length: String Utils) {
    Compute the <len: length> from <text>.
    Return an <OK: status> with <len>.
}

(* Test code — stripped from the binary *)
(length-of-hello: String Utils Test) {
    Given the <text> with "hello".
    When the <len> from the <get-length>.
    Then the <len> with 5.
}

Given / When / Then

ActionMeaningForm
GivenBind an input the feature set under test will readGiven the <name> with <value>.
WhenRun a feature set and capture its resultWhen the <result> from the <feature-set>.
ThenAssert the result equals an expected valueThen the <result> with <expected>.
AssertAssert a value directly, without a WhenAssert the <value> with <expected>.

A full file — several tests over the same production feature set:

(addition-test: Calculator Test) {
    Given the <a> with 15.
    Given the <b> with 7.
    Compute the <sum> from <a> + <b>.
    Then the <sum> with 22.
}

(complex-expression-test: Calculator Test) {
    Given the <price> with 50.
    Given the <quantity> with 3.
    Given the <tax-rate> with 0.08.
    Compute the <subtotal> from <price> * <quantity>.
    Compute the <tax> from <subtotal> * <tax-rate>.
    Compute the <total> from <subtotal> + <tax>.
    Then the <total> with 162.
}

Naming

A feature-set name cannot contain a reserved word — assert, when, to and friends are tokens, so (direct-assert: … Test) is a parse error. Name tests after what they check: length-of-blank, rejects-empty-cart.
